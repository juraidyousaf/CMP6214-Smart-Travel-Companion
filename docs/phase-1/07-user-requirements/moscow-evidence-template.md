# MoSCoW evidence template

**Official heading:** User Requirements  
**Template instruction:** Include a table or screenshot of your user requirements using the MoSCoW method.  
**Status: NOT STARTED.** Leave the table empty until you accept a requirement. Candidate needs in the synthesis are not rows. Brief-required flows such as checkout can be entered later with origin “brief”.

The brief spells the method “MoSCOW” in the submission list and the template uses “MoSCoW”. Use **MoSCoW**: Must, Should, Could, Won’t (this time).

If you explain the method, cite a source you have read. Do not cite this worksheet.

## Priority meanings for this project

| Priority | Meaning here |
|---|---|
| Must | The prototype fails the brief, or fails a sourced persona need, without it |
| Should | Important and evidenced, but the Week 9 demo can survive a simpler version |
| Could | Useful if time remains after Must and Should |
| Won’t | Considered and left out of this version. Record why, so the choice is visible |

A brief requirement such as checkout is a Must for the assignment even if no tourist source mentioned payment. Mark those rows **Origin: brief** so they are not mistaken for user research.

A persona need is a Must or Should only with a source ID.
